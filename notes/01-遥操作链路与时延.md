# 遥操作链路与时延

## 链路

```
主端（VR 头显 / 手柄 / 主从设备）
   → 指令编码
   → 网络传输
   → 从端控制器（运动学解算、安全校验）
   → 机械臂 / 底盘执行
   → 摄像头回传 → 人眼
```

任何一段慢，人都会觉得"不跟手"。

## 延迟和抖动是两件事

| 指标 | 含义 | 人的感受 |
|---|---|---|
| 延迟（latency） | 从动到看到结果的时间 | 稳定的慢，能适应 |
| 抖动（jitter） | 延迟忽大忽小 | 最难受，容易过冲、撞东西 |

**结论：稳定 150ms 比 80—300ms 乱跳好用得多。**

## 经验阈值

| 端到端延迟 | 体验 |
|---|---|
| < 100 ms | 接近直觉操作 |
| 100—200 ms | 可接受，精细任务会保守 |
| > 250 ms | 明显"追不上"，抓取成功率下降 |

控制周期另算：力控常要求 1 kHz，位置控制 100 Hz 级别。

## 现场现象的排查顺序

画面冻结 + 动作停止，按这个顺序查：

1. **链路**：网线/WiFi、交换机、丢包率、心跳。
2. **主端**：头显/手柄是否还在发心跳。
3. **从端**：控制循环是否还在跑（看门狗有没有喂）。
4. **算力**：CPU/GPU 占用、日志里的超时。

**先链路，后算力。** 大多数"卡死"是断链，不是算法跑不动。

## 测量方法

- 打时间戳：主端发指令时记 `t1`，从端收到记 `t2`，回传画面帧记 `t3`。
- 秒表法：做一个固定动作（抬手），录屏数帧，粗算总延迟。
- 抓包：看往返时间（RTT）和丢包率。

## 一句话版本（面试可用）

> 遥操作里延迟和抖动要分开看，抖动更伤人。我们现场遇到画面冻结、动作停止，排查顺序是先看通信链路和心跳，再看控制循环，最后才是算力。
