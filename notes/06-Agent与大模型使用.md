# Agent 与大模型：怎么用才不是"聊天玩具"

> 现场听到合伙人聊 Agent 和 Claude。这篇写清楚三件事：Agent 是什么、Claude 强在哪、你在实习里能怎么用。

## 一、Agent 是什么

**一句话：能自己调工具、自己多步执行的模型。**

普通对话：你问一句，它答一句。
Agent：你给目标，它拆步骤 → 调工具（搜索、代码、文件、机器人 API）→ 看结果 → 再决定下一步，直到完成。

三个必要件：

| 组件 | 作用 | 例子 |
|---|---|---|
| 模型 | 决策与规划 | Claude、DeepSeek、Qwen |
| 工具 | 真正干活 | 读文件、跑代码、调机器人控制接口 |
| 循环 | 观察→思考→行动，直到结束 | ReAct 范式 |

工程上的关键接口叫 **function calling / tool use**：你告诉模型"有这么几个函数、参数长什么样"，它决定什么时候调用、传什么参数。协议层现在常提 **MCP**（模型上下文协议），本质就是"给模型统一插工具"。

## 二、Claude 强在哪，弱在哪

**强**：长上下文（一次能读很长的文档/日志）、工具调用稳定、写代码和改代码靠谱、Computer Use 能操作界面。

**弱（对你而言）**：

- 官方服务不对中国大陆开放，第三方中转存在**合规、数据出境、封号**三重风险；
- 合伙人们说的"维护好收益高"，很大一部分成本就是维护这种不稳定通道。

**国内可替代**：DeepSeek、通义千问（Qwen）、Kimi、GLM、豆包。差别在长上下文和工具调用的稳定性，日常够用。

## 三、你在实习里能用的五个场景

### 1. 方案生成（代替"让 AI 画图"）

不要问"帮我设计一个推门工具"，要给约束：

```
已知：门厚 40mm，圆把手直径 20mm，门缝 12mm，夹爪最大开口 60mm，
开门力约 30N。请给出 3 种末端工具方案，用表格对比结构、材料、
优点、风险，并指出每种方案最可能失败的环节。
```

### 2. 故障分析（代替"直接问答案"）

```
现象：换电池后 30 秒内，机械臂出现 3—5 秒剧烈抖动，之后恢复。
已知：绳驱臂，7 自由度，换电时系统不断电。
请列出可能原因，按可能性排序，并给出每条原因对应的验证方法
（要看什么日志/测什么信号）。
```

关键在于要**验证方法**，不只给结论。

### 3. 反向学习（代替"让它讲一遍"）

```
我在学"看门狗机制"。请出 5 道判断题考我，我答完你再逐题讲解，
不要一次给答案。
```

### 4. 文档与汇报

```
把下面这段现场记录改写成周报，三段：本周完成、遇到的问题、
下周计划。每段不超过 3 行，不要形容词。
```

### 5. 面试模拟

```
你是吉利设备岗面试官，根据我的简历（附后）追问 5 个问题，
每个问题追问一层细节，不要提前给答案。
```

## 四、三条红线

1. **公司数据不上传**：客户信息、酒店地址、图纸、含 IP/序列号的日志，一律脱敏或不用。
2. **AI 的输出只是假设**：方案、根因都要拿现场验证，别把"模型说"当"事实"。
3. **别在公开场合评价公司技术选型**：你听到的"Claude 强/国内不稳"是团队判断，写进公开仓库要谨慎。

## 五、和你的岗位有什么关系

吉利设备岗、测试岗不考 Agent，但考"会不会用工具提效"。
面试可以说：

> 我会用大模型做方案对比和故障假设排序，但结论一定回到现场验证——
> 比如推门工具，我先让它列三种结构，再用纸板原型实测。

这句话的分量，比"我会用 ChatGPT"高得多。
