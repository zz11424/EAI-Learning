# 数据管线与数据质量

## 链路

```
边缘端采集（视频 / 点云 / 关节角 / 力 / IMU）
   → 本地缓存
   → 上传
   → NAS 归档（按日期 + 人员）
   → 清洗（去重、去无效段）
   → 标注（任务、成功/失败、场景标签）
   → 训练
```

任何一环偷懒，后面全白干。

## 三个容易被忽略、但决定成败的点

### 1. 时间同步

视频帧、关节轨迹、力信号必须对齐到同一时钟（PTP / NTP），否则"动作—画面"错位，标出来的数据是废的。

**检查方法**：取一段"手碰到门把手"的片段，看视频帧时间和力信号突变时间是否对得上。

### 2. 丢帧检测

和 CAN 报文一个道理：用计数器/序号判断断档。

- 轨迹点序号是否连续；
- 时间戳是否跳变（间隔突然变大）；
- 视频帧率是否掉。

本项目里正好做过同类分析：2994 帧、平均周期 20.04 ms、检出 6 帧丢失。**方法完全一样，只是对象从报文换成轨迹。**

### 3. 元数据规范

每条数据至少要有：日期、人员、任务、场景、成功/失败、时长。

少一个字段，三个月后这批数据就没人敢用——**不知道它是什么，就等于没有**。

## 评测四个指标

| 指标 | 定义 | 用途 |
|---|---|---|
| 成功率 | 完成任务次数 / 总次数 | 能力上限 |
| 单任务耗时 | 从开始到完成 | 效率 |
| 重试次数 | 同一任务重复操作次数 | 稳定性 |
| 人工干预率 | 需要人接管的次数占比 | 自动化程度 |

这四个数字，就是现场每天该记的东西，也是三个月后报告的全部。
